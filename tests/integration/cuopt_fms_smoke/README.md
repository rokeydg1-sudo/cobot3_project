# cuOpt → FMS → ROS 2 → Isaac Sim Integration Smoke Test

## Purpose

This is the minimal integration baseline for verifying the full data flow:

cuOpt → route result → FMS → ROS 2 → Isaac Sim → AMR feedback → FMS

This test intentionally keeps each component simple so that communication or environment problems can be isolated easily.

> This directory represents the smoke-test architecture, not the final production architecture.

## Execution order

### Terminal 1 — cuOpt Solver

Run `01_local_cuopt_solver.py` with a Python environment where NVIDIA cuOpt is installed.

It:

- builds a simple routing problem
- solves it with cuOpt
- creates `cuopt_route.json`
- exits

Expected marker:

`RESULT    : CUOPT_ROUTE_READY`

### Terminal 2 — Isaac Sim

Run `02_isaac_simple_world.py` with Isaac Sim's Python wrapper.

It:

- starts Isaac Sim
- creates a minimal physical world
- creates a simple AMR cube
- receives FMS goals through ROS 2
- publishes AMR pose and status

For Isaac Sim 5.1 on Ubuntu 24.04, use Isaac Sim's internal ROS 2 Jazzy environment rather than sourcing the system ROS 2 Python environment.

Expected marker:

`STATE ISAAC_READY`

### Terminal 3 — FMS

Run `03_simple_fms.py` with the system ROS 2 Jazzy Python environment.

It:

- reads `cuopt_route.json`
- dispatches each route goal
- receives AMR pose/status feedback
- advances to the next destination

Expected final marker:

`MISSION COMPLETE`

## ROS 2 interfaces

- `/fms/goal` — `geometry_msgs/msg/Point` — FMS → Isaac Sim
- `/amr/pose` — `geometry_msgs/msg/Point` — Isaac Sim → FMS
- `/amr/status` — `std_msgs/msg/String` — Isaac Sim → FMS

## Shared logical locations

- `0`: Depot `(0, 0)`
- `1`: Parts Supermarket `(-3, 2)`
- `2`: Assembly Cell A `(3, 2)`
- `3`: Assembly Cell B `(3, -2)`

## Environment separation used by this smoke test

This test was validated using three execution environments:

- cuOpt solver: local cuOpt Python environment
- FMS: system ROS 2 Jazzy / Python 3.12
- Isaac Sim: Isaac Sim 5.1 / Python 3.11 / internal ROS 2 Jazzy

This separation is intentional for the smoke test.

The actual project may combine FMS and cuOpt into one Python 3.12 virtual environment after compatibility is verified.

## Generated files

`cuopt_route.json` is generated by `01_local_cuopt_solver.py`.

It is runtime output and is not committed to Git.
